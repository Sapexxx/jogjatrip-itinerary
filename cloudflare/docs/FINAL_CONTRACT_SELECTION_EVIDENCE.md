# Contract 0.2 — local schema and material selection acceptance

Source of truth: the 20 canonical ZIP files verified by `tools/check-source-manifest.mjs`. They remain unchanged. `tools/check-consumer-schemas.test.mjs` uses the exact seven JSON schemas with pinned AJV and format validation. It tests both synthetic HTTP responses and outgoing serialized HOLD, including negative cases. It is not the remote official provider checker.

`src/interop-selection.ts` is a server-owned, read-only verifier for the existing provider availability APIs. It independently compares the chosen room, capacity, ticket destination/date/quantity/base tier or rental option and total with the canonical offer. The adapter awaits the verifier and fails closed; no reliance on display attributes. Hotel offer resourceId is the room ID as emitted by the inspected hotel source. Transport offers are signed for the requested driver option in the inspected transport source. Wisata signed offers are for base tier only in the inspected source. These provider-specific mappings require confirmation against actual staging revisions; they do not change the master contract. Unsupported tier, ambiguity, bad data, failed GET or mismatch blocks the offer. No provider POST, legacy fallback or public saga wiring added. Server policy must not be selected from browser input.

CI installs pinned tools dependencies and runs the schema suite, then Worker and Go checks. All provider calls in the added tests use synthetic fixtures. No production or staging credentials used. E8/E9 real staging and W2 durability remain separate release gates. The verifier exists as an injectable policy but is not connected to the public preparation route in this change.
