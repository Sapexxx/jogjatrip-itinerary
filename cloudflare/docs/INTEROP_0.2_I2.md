## Policy and API

`createProviderAdapter(env, fetcher, policy)` exposes read-only `detect(kind)`, `chooseMode(request)`, `prepareCheckout(request)`. No mutation methods. `INTEROP_HOLDS` defaults false; only literal 'true' enables detection. Add optional type bindings only; no wrangler change. `BOOKING_ENABLED` is independent, false in production. Capabilities authenticated via I1 (3s default), per required provider only, parallel; check version/provider through I1, holds, durableStorage, entityTypes and positive TTL. A positive TTL may be shortened for test; I4 will require actual expiry/safety margin. Capability success is not proof of actual storage durability; staging evidence required. Missing credentials, unsupported endpoints, malformed response and timeout report distinct sanitized reasons.

Mode choice: CONTRACT_0_2 only if all required providers eligible, no duplicate provider per shared externalRef (temporary conservative restriction); LEGACY only explicit request plus server allowLegacy policy and configured legacy bindings, never automatic fallback. Legacy configuration readiness is not an availability/health claim. BLOCKED if requested contract fails. Once mutationStarted, reject any mode reselection; I3/I4 must persist this state server-side and reconcile. Existing routes remain unchanged; never use incoming user flags as authority.

Map ServiceItem hotel check-in/out exclusive, quantity 1 room (guests not units); wisata visit date and ticket quantity; transport inclusive date and quantity 1. Master offers query only, no invented tier/driver/room filters. Provider offerId opaque, totalPrice authoritative, no recomputation. Fetch only after all required capabilities eligible. No selection based on display-only attributes. Master doesn't establish canonical lodging resourceId identity (hotel vs room), or how to verify room capacity, ticket tier or driver option. Exact resourceId plus trusted server-only resolver (mandatory for hotel) and verifier are required. No production verifier is implemented: fail closed absent proof, mismatch, ambiguity, missing offer (limit 20, no pagination defined), insufficient stock or failed request. Synthetic fixture proof only exercises logic. Do not expose verifier to client input or rely on attributes. Team must agree on authoritative mapping/options before live integration. Distinguish preflightComplete (all read-only selections verified) from bookingEnabled; neither makes a reservation. I4 must check flag, persist mode and revalidate price/expiry before mutations. No automatic substitute, no mixed legacy/hold mode.
