# I5 frontend consent and prepare-only integration

Plan checkout has two unchecked approvals: customer-data consent and exact simulated quote total. The form resets approvals on selection/quote revision or customer changes. Only saved plans are eligible; cart remains draft-only. The same-origin authenticated POST sends the explicitly approved material selection and price, and the backend compares these against the server-owned plan before provider preflight. No provider POST, HOLD, CONFIRM, payment or legacy booking is invoked. The server-owned material verifier is injected only if INTEROP_HOLDS=true, INTEROP_PREPARE_ENABLED=true, BOOKING_ENABLED=false; existing default config remains unchanged. Browser storage contains only draft fingerprint/key/state and nonsecret order ID. Checkout token is generated before the request and shown in the existing password field, not stored or included in URL. A missing or uncertain response locks the local draft; no automatic replay. Full token custody/recovery and internal saga bridge are separate next work. No production feature flag enabled. Tests use fixtures only.
